1. 프로젝트 개요
1.1 배경 및 목적
KT 나스미디어의 nap ssp SDK는 Android (Java/Kotlin) 및 iOS (Swift/Objective-C) 네이티브 환경에서만 공식 지원됩니다. 하지만 현재 많은 모바일 앱 개발사들이 코드 재사용성, 개발 효율성, 유지보수 편의성을 이유로 React Native 기반의 크로스플랫폼 개발을 채택하고 있습니다.

본 프로젝트는 nap ssp의 Android / iOS 네이티브 SDK를 React Native 환경에서 사용할 수 있도록 하는 공식 React Native 플러그인(npm 패키지) 개발 계획서입니다. 네이티브 브리지 방식을 통해 기존 SDK의 기능을 100% 보존하면서도 JavaScript/TypeScript 인터페이스로 광고를 손쉽게 연동할 수 있는 환경을 제공하는 것이 핵심 목표입니다.

📌 핵심 가치
• 네이티브 SDK 성능 완전 보존 (Native Bridge 방식)
• TypeScript 타입 안전성 제공
• React Native New Architecture (Fabric/JSI) 대응
• 단일 코드베이스로 Android/iOS 동시 지원

2. 기술 설계
2.1 아키텍처 개요
React Native 플러그인은 Native Module 및 Native View Manager 패턴을 기반으로 설계됩니다. JavaScript 레이어에서 API를 호출하면 React Native Bridge(또는 JSI)를 통해 네이티브 레이어의 nap ssp SDK를 직접 호출합니다.

⚙️ 아키텍처 레이어 구조
[JS/TS Layer]
  NapSspAd.initialize() / BannerAd / InterstitialAd / RewardedAd
       ↕  React Native Bridge (Old Arch) / JSI (New Arch)
[Native Module Layer]
  Android: NapSspModule.kt (ReactContextBaseJavaModule)
  iOS:     NapSspModule.swift (RCTBridgeModule)
       ↕  Direct SDK Call
[SDK Layer]
  Android: admixer-ssp (Maven)
  iOS:     AdMixerMediation (CocoaPods / SPM)

2.3.4 리워드 광고
// src/RewardedAd.ts
 
interface RewardItem {
  type: string;
  amount: number;
}
 
class RewardedAd {
  constructor(adUnitId: string);
  load(): Promise<void>;
  show(): Promise<void>;
  addAdEventListener(event: 'onRewarded', handler: (reward: RewardItem) => void): () => void;
  addAdEventListener(event: AdEventType, handler: () => void): () => void;
  destroy(): void;
}
 
// 사용 예시 (리워드 이벤트 EARNEDREWARD 콜백 대응)
const rewarded = new RewardedAd('your-adunit-id');
rewarded.addAdEventListener('onRewarded', (reward) => {
  console.log('보상 획득:', reward.type, reward.amount);
});


3. 개발 환경 및 의존성
3.1 Android 설정
플러그인의 android/build.gradle에 아래 의존성을 포함시킵니다. 앱 개발자가 직접 설정할 필요 없이 플러그인 설치만으로 자동 적용됩니다.

// android/build.gradle
 
dependencies {
    // (필수) nap ssp Core SDK
    implementation 'io.github.nasmedia-tech:admixer-ssp:1.0.21'
    implementation 'com.google.android.gms:play-services-ads-identifier:18.9.0'
 
    // (선택) 미디에이션 - 사용자 설정에 따라 조건부 포함
    compileOnly 'io.github.nasmedia-tech:admixer-admanager:1.0.14'
    compileOnly 'io.github.nasmedia-tech:admixer-adfit:1.0.10'
    compileOnly 'io.github.nasmedia-tech:admixer-pangle:1.0.10'
    compileOnly 'io.github.nasmedia-tech:admixer-applovin:1.0.8'
    compileOnly 'io.github.nasmedia-tech:admixer-unity:1.0.6'
}
 
// Adfit, Pangle 리포지토리
repositories {
    maven { url 'https://devrepo.kakao.com/nexus/content/groups/public/' }
    maven { url "https://artifact.bytedance.com/repository/pangle/" }
}

⚠️ Proguard 자동 적용
플러그인은 consumer-rules.pro를 통해 Proguard 규칙을 자동으로 앱 프로젝트에 전파합니다. 별도 Proguard 설정 없이 난독화 대상에서 nap ssp 클래스가 자동 제외됩니다.

3.2 iOS 설정
플러그인의 NapSspPlugin.podspec에 의존성을 정의합니다. 미디에이션 네트워크는 optional dependency로 관리하여 앱 개발자가 필요한 것만 선택적으로 설치할 수 있습니다.

# NapSspPlugin.podspec
 
Pod::Spec.new do |s|
  s.name         = 'NapSspPlugin'
  s.version      = '1.0.0'
  s.summary      = 'React Native plugin for KT Nasmedia nap ssp SDK'
  s.platform     = :ios, '13.0'
 
  # 필수 의존성
  s.dependency 'AdMixerMediation'
  s.dependency 'React-Core'
 
  # 미디에이션 (subspecs로 분리)
end
 
# 앱의 Podfile 설정 예시
target 'MyApp' do
  use_frameworks!
  pod 'NapSspPlugin'
  pod 'NapSspPlugin/GAM'        # Google AdManager 미디에이션
  pod 'NapSspPlugin/AdFit'      # Kakao AdFit 미디에이션
  pod 'NapSspPlugin/Pangle'     # Pangle 미디에이션
  pod 'NapSspPlugin/AppLovin'   # AppLovin 미디에이션
  pod 'NapSspPlugin/UnityAds'   # UnityAds 미디에이션
end

📱 ATT (App Tracking Transparency) 처리
iOS 14.5+ 환경에서 ATT 권한 요청은 AppDelegate에서 직접 처리해야 합니다. 플러그인은 ATT 요청 유틸리티 함수를 제공하며, 앱 개발자가 적절한 시점에 호출할 수 있도록 가이드합니다.

• TurboModules (JSI 기반 Native Module) 지원
• Fabric (Native UI Component) 지원
• backward compatible — RN 0.72~ 에서도 동작

	•	NativeModule → TurboModule 포팅 (C++ JSI 인터페이스)
	•	NativeView → Fabric Component 포팅
	•	Old Arch / New Arch 자동 감지 및 분기 처리

6. 주요 고려사항 및 제약사항
6.1 Media Key 제약사항
⚠️ 중요 제약사항
• 하나의 앱(App)에는 하나의 Media Key만 적용 가능합니다.
• 하나의 AdUnit ID는 하나의 광고 객체에서만 사용 가능합니다.
• 많은 AdUnit 사용 시 메모리 사용량 증가에 주의하세요.
• 광고 호출 전 반드시 초기화(initialize)를 완료해야 합니다.

6.2 네이티브 광고 레이아웃 제약
	•	네이티브 광고는 RelativeLayout 사용을 강력 권장합니다.
	•	동적 LayoutParams 변경은 미디에이션 사용 시 문제를 일으킬 수 있어 비권장입니다.
	•	RN에서는 네이티브 뷰를 직접 사용하므로, 레이아웃 변경은 네이티브 레이어에서 처리합니다.

6.3 Google 미디에이션 MCM 연동
	•	Google AdManager 미디에이션 사용 시 MCM(Multiple Customer Management) 연동 절차가 별도로 필요합니다.
	•	Google App ID는 nap ssp 운영팀(nap_adx@nasmedia.co.kr)에 문의하여 발급받아야 합니다.
	•	SDK 입찰 광고 소스(Pangle, AppLovin, DT Exchange, InMobi, Liftoff, Meta, Moloco, Unity, Mintegral) 라이브러리 추가 필요합니다.

6.4 Adfit 특이사항
	•	Adfit 상용 광고는 앱 심사 과정 이후에 응답됩니다.
	•	라이브 후 운영팀에 문의하여 심사를 진행해야 합니다.
	•	테스트 광고 → 매체 라이브 → Adfit 심사 → 상용 광고 순서로 진행됩니다.

6.5 네트워크 SDK 중복 사용
	•	앱 내에서 이미 동일 네트워크 SDK를 운영 중인 경우, Gradle exclude 처리를 통해 중복 예외 처리가 가능합니다.
	•	동일 지면에서 동일 네트워크 SDK를 통한 중복 광고 호출은 불가합니다.
	•	중복 사용 설정은 nap ssp 운영팀에 문의가 필요합니다.
